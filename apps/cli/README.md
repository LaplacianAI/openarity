# oa

The Openarity command-line client. Talks to a brain over its HTTP API.

Usage, the environment variables and the configuration file are documented in
the [root README](../../README.md#the-cli) — this file is for working on the
module itself.

## Build and run

```sh
make install    # go install ./cmd/oa — puts oa at $(go env GOPATH)/bin
make build      # or just compile into ./bin

oa --help
```

Requires Go 1.26.5. Nothing else — no database, no services.

## The gate

```sh
make check      # tidy, generate, format, vet, lint, build, race tests
```

Run it before saying anything is done. CI runs the same thing plus `make cover`
and `make vuln`, in the `cli` job of
[`.github/workflows/ci.yml`](../../.github/workflows/ci.yml).

```sh
make cover      # coverage, fails below 70%
make vuln       # govulncheck
make fmt        # apply gofumpt and fix import order
make tools      # reinstall tooling — rerun after a Go toolchain upgrade
```

Coverage excludes `internal/client`. It is roughly two thousand generated lines
nobody wrote, so counting it measures oapi-codegen rather than this module —
34.6% with it, 83.8% without.

## The generated client

`internal/client/client.gen.go` is generated by
[oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) from
`apps/brain/api/openapi.yaml`, and is **committed**.

```sh
make generate         # regenerate after the spec changes
make generate-check   # regenerate and fail if the committed copy differs
```

Never edit it — the next `make generate` overwrites the change. `generate-check`
runs in CI, and it is the job that catches a spec change landing in the brain
without the client being rebuilt.

The configuration is `oapi-codegen.yaml`. Two settings there are load-bearing:
`client: true` generates the typed `ClientWithResponses` that every command
uses, and `name-normalizer: ToCamelCaseWithInitialisms` is why the generated
names are `UserID` rather than `UserId`.

## Layout

```text
cmd/oa/            the commands, and the composition root
internal/theme/    what a theme is — one Parse, zero dependencies
internal/output/   what a format is
  printer/         how a value is rendered: json, yaml, table
internal/config/   the config file, and resolving a setting to a value
internal/auth/     which credential to send, and to whom
internal/ui/       colours, and whether the writer is a terminal
internal/client/   generated — never edited
```

`apps/brain/internal/` is unreachable from here: Go's `internal` rule is scoped
to the module root, and each app is its own module. Nothing is shared between
them but the spec.

## Testing against a real brain

Start one in another shell and `oa` needs no configuration — it finds the
development token in your environment and sends it, because the address is
loopback.

```sh
cd ../brain
export OPENARITY_DEV_TOKEN=letmein
export OPENARITY_SUPER_ADMINS=dev
make run

# back here
export OPENARITY_DEV_TOKEN=letmein
oa whoami
```

That token is sent **only** to a loopback address. Against anything else `oa`
asks you to log in rather than offering a shell secret to a host you may have
reached by a typo.
