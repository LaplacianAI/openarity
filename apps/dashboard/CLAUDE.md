# dashboard

The Openarity web dashboard: a React single-page app, built into the brain
binary and served at `/ui/`. It talks to the brain only through the brain's
HTTP API, the same one `oa` uses. What it is for and who it serves is
[PRODUCT.md](PRODUCT.md); how it looks is [DESIGN.md](DESIGN.md).

## Working agreement

The dashboard is **tier 2, all of it**: Claude writes it, and the user reviews
the design before anything is written (see the `working-agreement` skill, two
tiers). Design first still holds: a high-level and a low-level design, each
with a diagram, approved before code. Every edit is handed over with a link to
its file and line, grouped into a few large pieces.

## Skills

- **`add-a-screen`** — every new screen or route. Covers the route file, its
  place in `navGroups`, what ⌘K finds by itself, the capture plan, the page test
  and the gallery. Use it every time; a screen missing from the capture plan is
  never looked at again.
- **`call-an-endpoint`** — every new brain endpoint the dashboard uses. Covers
  the one function in `api/index.ts`, the wire type in `api/types.ts`, permissions,
  the dev proxy, and the fake brain's route in the test.
- **`write-tests`** — every test. Covers `brain()`, `team()`, `pageOf`,
  `showAt`, role queries, unit tests in `lib/`, coverage, and breaking each
  guard to see a test fail.
- **`fix-lint`** — any Biome or TypeScript failure.

## Layout

```text
apps/dashboard/
  src/
    main.tsx            mounts the router
    routes/             one file per screen, TanStack file routes:
      __root.tsx        the query client: no retries, no refetch on focus
                        ui.<name>.index.tsx, ui.<name>.$id.tsx, ui.<name>.new.tsx
      ui.tsx            the shell: sign-in gate, sidebar, rail, phone bar, ⌘K
    routeTree.gen.ts    generated by the router plugin; never edit by hand
    api/
      index.ts          one function per endpoint, and none without one
      client.ts         request(): the only place the app does HTTP
      types.ts          the wire types, transcribed from apps/brain/api/openapi.yaml
      permissions.ts    usePermissions(team).can("agent:write")
      session.ts        the current team, the token, renewal
      sse.ts            server-sent events read off a fetch body
    components/         shared pieces: states, status, ui-bits, facts, run-table,
                        run-detail, command-palette, ask-team, unsaved
      ui/               vendored shadcn primitives; not linted, not covered
    lib/                pure logic, each with its .test.ts beside it
    gallery/            every shared component in every state; dev builds only
    test/
      brain.tsx         the fake brain and the render helpers
      setup.ts          jsdom polyfills and the testing-library timeout
      pages/            one page test per screen
  scripts/              capture.mjs and capture/plan.mjs; seed-showcase.sh
```

`@` is `src/`.

## Commands

```sh
make deps        # npm ci
make dev         # vite on its own port, proxying the API to DASHBOARD_BRAIN
make check       # fmt-check lint typecheck cover build audit, as CI runs them
make fmt         # biome check --write
make test        # vitest once; make test-watch to keep it running
make capture label=<name>   # screenshot every screen against CAPTURE_BASE_URL;
                            # make capture-login first
```

`make dev` proxies `/auth`, `/teams`, `/users` and `/whoami` to
`DASHBOARD_BRAIN` (default `http://127.0.0.1:21120`). An endpoint under a new
top-level prefix needs adding to that list in `vite.config.ts`.

The brain embeds the build: `make ui` in `apps/brain` runs this app's `deps
build` and copies `dist/` into `internal/api/ui/dist`. This app's Makefile knows
nothing about the brain, and `dist` is never committed.

## Conventions

- **The brain still checks every route.** `usePermissions` decides only what a
  screen offers. While permissions are unknown, nothing is offered; if they fail
  to load, everything is, and the brain's refusal names itself.
- **A screen says what it takes rather than hiding it.** A write the caller
  cannot make is shown with the permission it needs.
- **No automatic retries.** Queries and mutations are set not to retry; a failure
  is something the operator should see.
- **The token lives in `sessionStorage`,** under `openarity.session`, and
  nowhere else.
- **`types.ts` is no richer than the server.** A field is added there when the
  brain's schema has it, and named as the JSON names it.
- **Filters live in the URL,** through the route's `validateSearch`, so a
  filtered view can be linked and survives a reload.
- **Styling follows DESIGN.md:** Spectral tokens from `styles.css`, no shadows,
  status as an icon beside a word (`StatusPill`), mono for ids only, sentence
  case, motion through the `--dur-*` and `--ease-*` tokens with reduced motion
  respected. Colours come from `BRAND.md`, and `src/test/palette.test.ts` fails
  when they drift.
- **Empty, error and forbidden states use `components/states.tsx`,** which keep
  a block's frame, rather than a one-off message.
